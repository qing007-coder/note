# 匈牙利算法（Hungarian Algorithm）

## 一句话

匈牙利算法解决的是**二分图最小代价匹配**：左边每个预测、右边每个 GT，给每一对计算代价，最后找一组一对一匹配，使总代价最小。

## 在 DETR 里的作用

DETR 输出固定数量的预测框，但目标数量不固定，而且预测框没有天然编号。因此训练时需要先回答：**哪个 prediction 对应哪个 GT？**

```text
N 个 prediction + M 个 GT
        ↓
计算 N×M 代价矩阵
        ↓
匈牙利算法求最小代价的一对一匹配
        ↓
匹配上的 prediction 计算分类和框损失
未匹配的 prediction 作为 no-object
```

## 代价矩阵怎么来

检测任务通常把三种代价加起来：

```text
cost(i,j) = λcls · 分类代价
          + λL1  · |预测框 - GT框|₁
          + λgiou · (1 - GIoU)
```

分类代价看类别是否一致，L1 约束框参数，GIoU 约束框的整体重叠和位置。

## 核心特点

- **一对一**：一个 GT 只匹配一个 prediction。
- **全局最优**：不是每个 prediction 各自找最近 GT，而是让整体总代价最小。
- **不参与反向传播**：匹配结果通常由 `no_grad` 下的离散算法得到；梯度通过匹配后的分类和回归损失传回网络。
- **不需要 NMS**：训练阶段已经约束一个目标只对应一个 prediction，推理时直接过滤低置信度结果。

## 一个小例子

假设有 3 个 prediction、2 个 GT：

```text
          GT1   GT2
Pred1      2     8
Pred2      1     3
Pred3      7     2
```

算法不会简单地让每个 prediction 都选最小值，因为 Pred2 和 Pred1 可能同时抢 GT1。它会寻找互不冲突的组合，例如 `Pred1→GT1, Pred3→GT2`，总代价为 `2+2=4`。

剩下的 prediction 不匹配任何 GT，被分配到 no-object 类。

## 面试重点

**问：为什么不用最近邻匹配？**

最近邻是局部贪心，可能多个 prediction 抢同一个 GT，导致匹配冲突；匈牙利算法直接求全局最优的一对一分配。

**问：匈牙利算法和 NMS 是什么关系？**

匈牙利算法用于**训练时 prediction 与 GT 的分配**；NMS 用于传统检测器推理时去重。DETR 通过一对一集合预测降低重复预测，因此推理时通常不需要 NMS。

**问：它解决的是最大匹配还是最小匹配？**

标准形式是最小代价匹配。如果原问题是最大相似度匹配，可以把相似度转成代价，例如 `cost = -similarity`。

## 复杂度

对于 `n×n` 代价矩阵，经典匈牙利算法复杂度为 `O(n³)`。DETR 中 query 数量通常是几百，代价矩阵规模可接受。

## 和集合损失的关系

匈牙利算法只负责决定匹配关系，真正训练网络的是匹配之后的损失：

```text
预测集合 + GT集合
      ↓ 匈牙利匹配
固定对应关系
      ↓
分类损失 + 框回归损失 + no-object损失
```

所以更准确的说法是：**DETR 使用匈牙利匹配构造集合损失**，而不是匈牙利算法本身完成检测。
