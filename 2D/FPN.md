# FPN（Feature Pyramid Network）笔记

> **一句话**：FPN 用「自顶向下 + 横向连接」把 backbone 中深层强语义、浅层高分辨率融合成一组**语义一致**的多尺度特征金字塔，让小目标也能用上强语义特征。
>
> **论文**：Lin et al., *Feature Pyramid Networks for Object Detection*, CVPR 2017
>
> **贯穿例子**：输入 `224×224` 彩色图，backbone 为 ResNet-50，图中有一辆 `32×32` 的小汽车。全文所有计算都跟着这张图走。

---

## 1. 要解决什么问题

目标检测中目标尺寸差异巨大，而 backbone 越深特征图越小、语义越强，三种旧方案都不理想：

| 方案 | 做法 | 缺点 |
|---|---|---|
| 图像金字塔 | 把原图缩放多份分别提特征 | 慢、显存大，推理时间 ×N |
| 单层预测 | 只用最后一层特征（如 Faster R-CNN 只用 C4） | 小目标在深层只剩几个像素 |
| SSD 式多尺度 | 直接取各 stage 特征各自预测 | 浅层特征语义太弱（只有低层纹理） |

**FPN 的思路**：不做图像金字塔，而是对「特征」做金字塔——把深层语义逐级"传回"浅层。

【贯穿例子】那辆 `32×32` 的小汽车：

- C5 的下采样率为 32，`224/32=7`，特征图只有 `7×7`——小车只剩 **1 个格子**，位置信息几乎没了；
- C2 的下采样率为 4，小车占 `32/4=8` 个格子，位置准，但 C2 是浅层特征："知道这里有东西"，却不知道是车；
- FPN 之后，P2 同时具备 **8 格分辨率 + C5 的语义** → 小目标可检。

## 2. 整体结构：三条路

```
C5  7x7x2048  ─1x1conv─► M5 7x7x256 ──3x3conv──► P5 7x7x256 ──s2──► P6 4x4x256
                              ▼ 2×最近邻上采样
C4 14x14x1024 ─1x1conv─► (+)──3x3conv──► P4 14x14x256
                              ▼ 2×最近邻上采样
C3  28x28x512 ─1x1conv─► (+)──3x3conv──► P3 28x28x256
                              ▼ 2×最近邻上采样
C2  56x56x256 ─1x1conv─► (+)──3x3conv──► P2 56x56x256
```

（`(+)` 为逐元素相加；`s2` 为 stride-2 下采样；Mk = up2(Mk+1) ⊕ conv1x1(Ck)）

- **自底向上**：backbone 正常前向，取每个 stage 最后一个 block 的输出 C2~C5；
- **自顶向下**：把更深层上采样 2 倍逐级往下传；
- **横向连接**：同尺寸的 C 层经 1×1 conv 对齐通道后，与上采样结果**逐元素相加**，再过 3×3 conv 消除上采样带来的混叠，得到 P 层。

所有 P 层统一输出 **256 通道**，对应步长：P2:s4、P3:s8、P4:s16、P5:s32、P6:s64。

【贯穿例子】完整尺寸流水账（输入 224×224）：

| 张量 | 来源 | 形状 |
|---|---|---|
| C2 | res2 输出 | 56×56×256 |
| C3 | res3 输出 | 28×28×512 |
| C4 | res4 输出 | 14×14×1024 |
| C5 | res5 输出 | 7×7×2048 |
| M5 | 1×1conv(C5) | 7×7×256 |
| M4 | up2(M5) ⊕ 1×1conv(C4) | 14×14×256 |
| M3 | up2(M4) ⊕ 1×1conv(C3) | 28×28×256 |
| M2 | up2(M3) ⊕ 1×1conv(C2) | 56×56×256 |
| P2~P5 | 3×3conv(M2~M5) | 与对应 M 相同 |
| P6 | stride2 下采样(C5) | 4×4×256 |

注意 **M2 里已经带有 C5 的语义**——这就是"语义回流"：小汽车的信息从 C5 一路加回 P2。

## 3. 逐个模块拆解（配合例子算）

### 3.1 横向连接：1×1 conv

作用：**只对齐通道数，不改变分辨率**。选 1×1 而不是 3×3：通道压缩不需要空间上下文，还省参数。

【贯穿例子】C5 是 7×7×2048，经 1×1 conv 变成 7×7×256，参数量 `2048×256≈52 万`；若用 3×3 conv 则要 ×9。

### 3.2 上采样：最近邻 ×2

尺寸翻倍。选最近邻而不是反卷积：无参数、实现简单，效果相当。

【贯穿例子】M5 是 7×7×256 → 上采样成 14×14×256，正好与 C4 上采样后的分辨率对齐，才能逐元素相加。

### 3.3 逐元素相加 + 3×3 conv

- 相加 = **深层语义（经上采样，语义强但偏"糊"）+ 浅层细节（定位准）** 融合到同一表示；
- 相加 vs concat：复现实验普遍表明两者差距不大，而相加不引入参数、更省显存，FPN 采用相加；
- 3×3 conv：平滑上采样带来的混叠/对齐误差，是每层输出 P 的最后一道变换。

【贯穿例子】写出 M4 的完整计算（忽略 batch 维）：

```
u   = up2(M5)        # 14×14×256，由 7×7 最近邻插值得到
c4' = conv1x1(C4)    # 14×14×1024 → 14×14×256
M4  = u + c4'        # 逐元素相加，14×14×256
P4  = conv3x3(M4)    # 14×14×256
```

那辆 32×32 的小车若落在 C4 的某个 4×4 区域上，此刻 M4 的对应区域已同时带有"这是车"（来自 M5 回流的语义）和"精确在哪"（来自 C4 的细节）。

### 3.4 P6 的两种来源

- **Faster R-CNN/FPN 原文**：P6 = C5 直接 stride-2 下采样；
- **RetinaNet**：P6 = P5 stride-2 卷积，P7 = P6 stride-2 卷积（从 P5 起级联，层级更细）。

【贯穿例子】P6 = 4×4×256，负责最大尺度 anchor（512²）。

### 3.5 所有层级共享同一套检测头

P2~P6 接**相同参数**的 RPN/RCNN 头（如 RPN 的 3×3 conv(256) + 两个 1×1 conv 分类/回归）。前提是 FPN 已把各层拉齐到**同一语义尺度**——这正是 SSD 式方案做不到的（SSD 各层语义强度不同，没法共享头）。

## 4. 特征怎么用：按尺度分配

### 4.1 RPN：每层放固定尺度的 anchor

| 层 | P2 | P3 | P4 | P5 | P6 |
|---|---|---|---|---|---|
| anchor 面积 | 32² | 64² | 128² | 256² | 512² |

每层再配 3 种长宽比 {1:1, 1:2, 2:1}。

【贯穿例子】32×32 的小车 → 命中 P2 上的 32² anchor；若它放大到 128×128，则改由 P4 负责。

### 4.2 Fast/Faster R-CNN：RoI 按大小选层

```
k = ⌊ k₀ + log₂( √(w·h) / 224 ) ⌋        # k₀ = 4，结果限幅到 [2, 5]
```

含义：以 224² 为基准尺寸，RoI 越大分配越深的层。

【贯穿例子】算四个候选框：

- 224×224：√(w·h)=224，log₂1=0 → k=4 → **P4**；
- 112×112：log₂(1/2)=−1 → k=3 → **P3**；
- 448×448：log₂2=1 → k=5 → **P5**；
- 100×200（非正方形）：√(w·h)=√20000≈141.4，log₂(141.4/224)≈−0.66 → k=⌊3.34⌋=3 → **P3**。

## 5. 最小实现（PyTorch）

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class FPN(nn.Module):
    """输入 [C2, C3, C4, C5]，输出 [P2, P3, P4, P5]"""
    def __init__(self, in_channels_list, out_channels=256):
        super().__init__()
        self.lateral = nn.ModuleList(
            [nn.Conv2d(c, out_channels, 1) for c in in_channels_list])
        self.output = nn.ModuleList(
            [nn.Conv2d(out_channels, out_channels, 3, padding=1)
             for _ in in_channels_list])

    def forward(self, feats):
        lat = [l(f) for l, f in zip(self.lateral, feats)]   # 各层对齐到 256 通道
        for i in range(len(lat) - 2, -1, -1):               # 自顶向下
            lat[i] = lat[i] + F.interpolate(
                lat[i + 1], size=lat[i].shape[-2:], mode="nearest")
        return [o(l) for o, l in zip(self.output, lat)]
```

用贯穿例子跑一遍：

```python
feats = [torch.randn(1, 256, 56, 56),     # C2
         torch.randn(1, 512, 28, 28),     # C3
         torch.randn(1, 1024, 14, 14),    # C4
         torch.randn(1, 2048, 7, 7)]      # C5

P2, P3, P4, P5 = FPN([256, 512, 1024, 2048])(feats)
print(P2.shape)  # torch.Size([1, 256, 56, 56])
print(P3.shape)  # torch.Size([1, 256, 28, 28])
print(P4.shape)  # torch.Size([1, 256, 14, 14])
print(P5.shape)  # torch.Size([1, 256, 7, 7])

# 如需 P6（Faster R-CNN 版）：对 C5 做 stride-2 下采样
# P6 = F.max_pool2d(feats[3], kernel_size=1, stride=2)   # → [1, 2048, 4, 4]
```

## 6. 效果与后续

- COCO test-dev 上 **Faster R-CNN + FPN 达到 36.2 AP**（单模型），明显高于单尺度基线；其中**小目标 AP 提升最明显**；
- RPN 提案质量：召回率（尤其 AR@1000）显著提升；
- 后续工作：
  - **Mask R-CNN**：RoIAlign 直接接到对应 P 层做实例分割；
  - **RetinaNet**：FPN + focal loss 的一阶段检测器；
  - **PANet**：在 FPN 之上再加一条自底向上的增强通路；
  - **BiFPN**（EfficientDet）：带可学习权重的双向融合、可重复堆叠；
  - 与 **U-Net** 的区别：U-Net 面向分割、用 concat 与深层监督，FPN 面向检测、用相加且各层共享检测头。

## 7. 速记卡

- 三条路：**自底向上**提特征 → **自顶向下**传语义 → **横向连接**补细节；
- 融合四步：1×1 对齐通道 → 2× 最近邻上采样 → **逐元素相加** → 3×3 平滑；
- 输出统一 256 通道；各层语义一致，所以**检测头共享**；
- 分配原则：**小目标用浅层（P2/P3，高分辨率），大目标用深层（P5/P6）**；
- RoI 选层：`k = ⌊4 + log₂(√(w·h)/224)⌋`，限幅 [2,5]；
- 记住贯穿例子：224 输入 → C5 只有 7×7 → 小汽车在 C5 只剩 1 个格子，一路相加回 P2（56×56）后小目标也能检出。
