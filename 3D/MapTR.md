# MapTR / MapTRv2：在线矢量化高精地图构建

> **一句话**：MapTR 把地图元素当成一组有结构的点来预测，而不是把道路涂成语义分割栅格；它用分层 query 表达“地图实例—实例中的点—点坐标”，并把同一条折线的等价点序排列纳入匹配。MapTRv2 保留这套表示与 Transformer 主干，进一步加入时序信息、一对多辅助匹配和稠密辅助监督，改善精度与收敛。
>
> **论文**：
> - Liao et al., *MapTR: Structured Modeling and Learning for Online Vectorized HD Map Construction*, ICLR 2023 Spotlight，arXiv: [2208.14437](https://arxiv.org/abs/2208.14437)
> - Liao et al., *MapTRv2: An End-to-End Framework for Online Vectorized HD Map Construction*, IJCV 2024，arXiv: [2308.05736](https://arxiv.org/abs/2308.05736)
>
> **代码**：[`hustvl/MapTR`](https://github.com/hustvl/MapTR)。配置、数据集和版本不同会带来具体维度与指标差异，本文重点解释方法，不把某一个配置的数值当成所有版本的固定值。

## 1. 任务：从多相机图像直接生成矢量地图

自动驾驶需要车道线、道路边界、人行横道等静态道路信息。传统 HD map 由专门测绘车辆离线生产；在线建图希望车辆仅凭当前传感器观测，实时恢复附近地图，供定位、预测和规划使用。

MapTR 关注的是**矢量化地图构建**：每个地图元素是带类别的几何点集，而非 BEV 上逐像素分类的 mask。以一条车道分界线为例，模型输出类别和一系列有序坐标点，点连起来就是折线。

矢量表示的好处是几何紧凑、拓扑结构清楚，方便下游规划直接使用；难点是点的顺序并不总是唯一。例如一条没有方向语义的边界线，从左到右或从右到左都表示同一条线。若训练时只接受一种人为顺序，会给正确预测错误惩罚。

## 2. 整体流程

```text
环视相机图像
    │
    ▼
图像 Backbone + FPN
    │ 多尺度图像特征
    ▼
BEV 特征提取（典型配置使用 BEVFormer 风格编码器）
    │
    ▼
MapTR Decoder：地图实例 query × 点 query
    │
    ├─ 地图类别分数
    └─ 每个实例的一组 BEV 点坐标
    │
    ▼
匈牙利匹配 + 置换等价点集损失
    │
    ▼
矢量地图元素（车道线 / 道路边界 / 人行横道等）
```

要把握两层表示：

1. **实例层**：一个 query 对应一个地图元素，例如一条车道线；
2. **点集层**：实例 query 下有多个 point query，共同描述该元素的形状。

这让网络能显式表达“一个实例由多个有结构的点构成”，而不是把所有点摊平为互不相关的坐标。

## 3. MapTR 的核心：置换等价点集建模

### 3.1 地图元素表示

把第 `i` 个地图实例写成：

```text
M_i = (c_i, P_i)
P_i = {p_i,1, p_i,2, ..., p_i,K}
p_i,k = (x_i,k, y_i,k)
```

`c_i` 是元素类别，`P_i` 是 BEV 平面内的 `K` 个点。对于折线，点通常沿线排列；对于闭合或具有方向歧义的形状，会存在多种同样合理的点序。

### 3.2 为什么普通点回归会出问题

假设 GT 折线有 20 个点。预测点集与 GT 的几何形状完全一致，但起点落在另一端。若损失逐点比较固定索引，预测点 1 会被拿去和 GT 点 1 比、预测点 20 和 GT 点 20 比，结果可能得到很大的坐标误差。

这不是几何预测错了，而是**序列化顺序不同**。MapTR 把一个 GT 地图元素扩展为多个等价排列：

```text
P, reverse(P), 以及任务定义允许的其他等价排列
```

预测只要与其中一种排列匹配得好，就应视为正确。论文把这种方式称为 **permutation-equivalent modeling（置换等价建模）**。对方向有语义的类别，可用其定义中合法的排列集合，不能不加区分地把任意打乱都当等价。

### 3.3 分层 query

Decoder 的 query 按地图结构组织，可理解为：

```text
instance query q_i
    └── point queries q_i,1 ... q_i,K
```

实例 query 聚合“这是什么地图元素、整体在哪里”的语义；点 query 表达元素内部各点的位置与局部特征。模型据此输出实例类别和 `K×2` 坐标。分层嵌入保留实例与组成点之间的关系，避免把地图表示退化成一长串无结构 token。

## 4. 训练目标与匹配

MapTR 是集合预测模型：输出数量固定，但场景中 GT 元素数目可变。训练时先为预测实例和 GT 实例构造代价，再用匈牙利算法做一对一匹配。

匹配代价一般由类别代价和几何点集代价构成。几何代价会在该 GT 所有合法等价点序中取最小值：

```text
L_point(P_pred, P_gt) = min_{π ∈ Π} Σ_k d(p_pred,k, p_gt,π(k))
```

其中 `Π` 是该类别允许的排列集合，`d` 通常是坐标的 L1 距离。匹配完成后，对正样本计算分类损失与点坐标回归损失；未匹配 query 作为背景。推理阶段按置信度筛选预测实例，不需要传统逐像素连通域后处理。

**关键区别**：匈牙利匹配解决“哪个预测实例对应哪个 GT 实例”；置换等价损失解决“同一个实例内部的点序如何对齐”。二者处理的是不同层次的排列问题。

## 5. MapTRv2 增加了什么

MapTRv2 沿用 MapTR 的核心矢量表示、分层 query 和置换等价学习框架，主要增强训练信号并引入时序上下文。

### 5.1 时序建模

单帧相机视野受遮挡、距离和光照影响，有些地图结构在当前帧不完整。v2 把历史帧的特征纳入当前帧地图预测，使模型能利用相邻观测补足暂时不可见或模糊的道路结构。

可以把数据流概括为：

```text
当前帧图像特征 + 历史帧特征（按自车运动关系对齐）
                  │
                  ▼
              当前帧地图预测
```

时序输入提供的是额外上下文，不改变地图元素仍由“类别 + 点集”表示这一核心设定。训练和推理时历史帧的使用方式、队列长度及对齐细节依赖具体配置。

### 5.2 一对多辅助匹配

标准 DETR 式一对一匹配有较强的集合约束，但每个 GT 只给一个预测 query 提供正向监督，早期训练时监督相对稀疏。v2 增加 **one-to-many auxiliary matching**：训练辅助分支允许一个 GT 与多个预测候选建立监督关系。

直观理解：主分支仍学习干净的一对一集合输出；辅助分支给更多 query 提供正样本梯度，帮助更快学会发现地图实例。它是训练辅助机制，不意味着推理时会把重复实例全部输出。

### 5.3 稠密辅助监督

v2 还加入 dense supervision，让中间或辅助表征也获得更直接的地图监督，而不只依赖最终实例集合损失。这样可以改善优化信号稀疏的问题，并与一对多匹配共同加速收敛、提升检测质量。

记忆时可区分：

| 机制 | 主要解决的问题 | 是否改变最终输出表示 |
|---|---|---|
| 时序建模 | 当前帧观测不完整、遮挡和瞬时噪声 | 否，仍输出矢量实例 |
| 一对多辅助匹配 | 一对一训练监督较稀疏、收敛较慢 | 否，属于训练辅助 |
| 稠密辅助监督 | 仅监督最终集合带来的梯度不足 | 否，属于训练辅助 |

## 6. MapTR 与 MapTRv2 对照

| 方面 | MapTR | MapTRv2 |
|---|---|---|
| 核心任务 | 在线矢量化 HD 地图构建 | 同左 |
| 地图表达 | 类别 + 结构化点集 | 沿用 MapTR |
| 顺序歧义 | 置换等价建模，在合法点序中匹配 | 沿用 MapTR |
| Query | 分层地图实例 / 点 query | 沿用并配合增强训练 |
| 主要扩展 | 建立结构化集合预测框架 | 时序上下文、一对多辅助匹配、稠密辅助监督 |
| 改进重点 | 表示与集合学习 | 特征利用、训练监督密度和收敛 |

## 7. 和 BEV segmentation 的差别

| 对比 | BEV 栅格分割 | MapTR 系列 |
|---|---|---|
| 输出 | 每个栅格一个类别 | 若干地图实例及其点坐标 |
| 几何表达 | 离散像素，边缘受分辨率影响 | 连续矢量点，形状更紧凑 |
| 实例关系 | 往往需连通域或额外矢量化 | query 直接预测实例 |
| 训练核心 | 像素级分类 | 实例集合匹配 + 点集回归 |
| 主要挑战 | 栅格分辨率、实例连接 | 点序排列歧义、集合匹配 |

MapTR 的贡献不只是“用 Transformer 输出折线”，关键在于让网络的结构化输出、匹配规则和几何等价关系一致：地图实例是集合，点序可能等价，训练目标就必须承认这种等价。

## 8. 优点与局限

**优点**

- 矢量点集直接表达地图几何，紧凑且便于下游规划使用；
- 分层 query 保留地图元素和组成点的结构；
- 置换等价监督减少任意点序带来的错误惩罚；
- v2 的历史特征和辅助监督提升了信息利用与训练效率。

**局限**

- 点数 `K`、地图范围和类别定义仍需针对数据集设计；
- 远距离小结构、严重遮挡或图像纹理相似区域容易产生定位误差；
- 时序模型依赖坐标对齐、历史缓存和稳定的车辆运动信息；
- 输出是局部在线地图预测，不等同于拥有全局拓扑、跨行程一致性的完整 HD map。

## 9. 读论文时抓住这几件事

1. **问题是什么？** 从相机图像在线构建道路矢量地图。
2. **表示是什么？** 一个地图元素对应一个实例 query，元素由一组点描述。
3. **核心难点是什么？** 点序不唯一，固定序列回归会惩罚几何上正确的结果。
4. **MapTR 怎么处理？** 建模合法等价排列，并在匹配/损失中选择最佳点序。
5. **v2 增强在哪里？** 用历史特征提供时序上下文，用一对多匹配和稠密监督增加训练信号。

> 记忆口诀：**MapTR 把地图变成实例点集，并让等价点序都算对；MapTRv2 再补时间信息和更密集的训练监督。**
