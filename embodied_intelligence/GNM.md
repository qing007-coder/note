# GNM：从视觉观测与目标图像回归导航航点

> GNM = General Navigation Model。主线是“历史观测 + 目标图像 → CNN 编码 → 特征融合 → 距离与未来航点”。
>
> 导航阅读顺序：GNM → [ViNT](ViNT.md) → [NoMaD](NoMaD.md)。

## 1. 它在导航中做什么？

给机器人一段最近看到的图像，再给一张“想去的位置长什么样”的目标图像，预测：

1. **到目标的时间距离**：用于判断目标远近、选择子目标。
2. **未来一小段局部航点**：交给底层控制器去跟踪。

```text
历史 + 当前图像 O_t ──┐
                     ├─ GNM ──┬─ d_hat：到目标的时间距离
目标图像 g ──────────┘        └─ W_hat：局部坐标系中的未来航点
                                              │
                                              ▼
                                     底层控制器 → 速度 / 转向
```

GNM 的重点也包括多机器人数据训练和统一动作表示，让同一个视觉导航模型能跨机器人使用。输出归一化航点比直接输出某种机器人的电机指令更容易迁移。

## 2. 本篇采用哪个实现与形状？

以下结构按作者团队的 `visualnav-transformer` 仓库中 **GNM baseline 实现**说明，不把不同仓库、不同配置的细节混在一起。

| 符号 | 含义 | 配置示例 |
|---|---|---:|
| `B` | batch size | 2 |
| `C` | 历史帧数，不含当前帧 | 5 |
| `T=C+1` | 总观测帧数 | 6 |
| `H, W` | 图像高、宽 | 64, 85 |
| `P` | 预测航点数 | 5 |
| `Da` | 每航点维度 | 4，启用朝向预测 |

```text
逻辑观测序列 O          [B, T, 3, H, W] = [2, 6, 3, 64, 85]
实际 obs_img            [B, 3T, H, W]   = [2, 18, 64, 85]
目标 goal_img           [B, 3, H, W]    = [2, 3, 64, 85]
距离标签 distance       [B] 或 [B,1]
未来航点标签 W          [B, P, Da]      = [2, 5, 4]
```

`context_size=5` 表示 5 张历史图像，再加当前帧，共 6 张。**历史帧在输入通道维堆叠，不是先变成 6 个 Transformer token。**

## 3. 总架构：两个 CNN 分支 + 两个预测头

```text
obs_img [B,18,H,W] ──────────────┐
       │                        │
       ▼ 观测 MobileNetV2       │ 与 goal_img [B,3,H,W] 沿通道拼接
   [B,1280,hf,wf]               ▼
       │ GAP + flatten       [B,21,H,W]
       ▼                        │ 目标条件 MobileNetV2
   [B,1280]                     ▼
       │ Linear + ReLU      [B,1280,hf,wf]
       ▼                        │ GAP + flatten
   [B,1024]                     ▼
       │                    [B,1280]
       │                        │ MLP：1280 → 1024 → 1024
       │                        ▼
       └────── concat ───── [B,1024]
                    │
                    ▼
                [B,2048]
                    │ MLP：2048 → 256 → 32
                    ▼
                [B,32]
                    ├─ Linear(32 → 1)    → d_hat [B,1]
                    └─ Linear(32 → P*Da) → raw   [B,20]
                                                │ reshape
                                                ▼
                                            [B,5,4]
```

GAP = 全局平均池化，把空间网格汇聚成一个向量：`[B,1280,hf,wf] → [B,1280]`。以该 MobileNetV2 配置和 `64×85` 输入，末层空间网格为 `2×3`。

## 4. 两个分支分别在学什么？

### 观测分支

```text
最近 T 帧 ── 通道堆叠 ── MobileNetV2 ──> 观测向量 [B,1024]
```

它编码机器人附近的视觉环境，以及历史图像隐含的运动线索。第一层卷积直接接收 `3T` 个通道，多个时间帧从较早的卷积阶段开始混合。

### 目标条件分支

```text
[历史与当前观测, 目标图像] ── 通道拼接 ── MobileNetV2 ──> 目标条件向量 [B,1024]
```

该 baseline 的实际输入是 **整段观测堆叠 + 目标图像**，即 `3(T+1)=21` 通道，不能误写成只输入目标图像。

这两个 CNN 分支结构相似，但参数独立。目标分支学习观测和目标之间的关系，而不是只给目标图像做分类。

## 5. 输出为什么还需要后处理？

模型预测头的前两维是相邻航点的位置增量：

```text
raw[:, :, :2]            [B,P,2]   # 每步 dx、dy
          │ 沿航点时间维 cumsum
          ▼
W_hat[:, :, :2]          [B,P,2]   # 相对于当前机器人原点的航点坐标
```

若增量为 `[(1,0), (1,0.2), (1,0.2)]`，累积后航点为 `[(1,0), (2,0.2), (3,0.4)]`。

当 `learn_angle=True`：

```text
每个航点 = [x, y, cos(theta), sin(theta)]
                              │
                 后两维按向量做 L2 normalize
```

用二维单位向量表示朝向，可以避免角度在 `-pi / pi` 附近的跳变。关闭朝向预测后，`Da=2`，形状改为 `[B,P,2]`。

## 6. 距离 d 不是激光测距或米数

训练中的距离监督来自轨迹里的时间间隔 / 帧间隔，用来表示目标在导航意义上有多远。它是**时间距离的代理量**，不应直接解释为欧氏距离多少米。

```text
同一轨迹：当前帧索引 t，目标帧索引 g
                     │
                     ▼
       用按数据采样规则处理的时间间隔构造距离监督
```

航点也做尺度归一化，以减少不同机器人速度、数据采样间隔的差异。执行时再恢复到部署机器人的运动尺度。

## 7. 训练和闭环执行的数据流

### 训练

```text
轨迹日志：图像 + 位姿
      │
      ├─ 取历史 / 当前图像 → obs_img
      ├─ 取未来目标帧     → goal_img、时间距离标签
      └─ 从位姿提取未来轨迹 → 转当前局部坐标系 → 归一化航点标签
      │
      ▼ GNM
预测距离 + 预测航点
      │
      ▼ 距离回归损失 + 航点回归损失
```

跨轨迹等负目标可以用于距离 / 可达性学习，但没有相应真实动作时，不应硬凑一条到达该目标的轨迹监督；实现通过动作有效性 mask 等规则控制损失。

### 执行

```text
最近 T 帧 + 目标 / 子目标图像
         │
         ▼ GNM
预测 d_hat 与 W_hat [1,P,Da]
         │
         ▼ 取某个前方航点、恢复运动尺度
底层控制器生成线速度、角速度等机器人指令
         │
         ▼ 执行一小段，获取新图像，再次预测
```

长距离导航可配合拓扑地图：地图节点保存地点图像，通过预测距离做局部定位、推进子目标。GNM 是局部导航模型，完整系统还需要目标选择和控制环。

## 8. 为什么下一步会发展到 ViNT？

GNM 已经把“跨机器人视觉输入 → 统一航点输出”的接口建立起来，但时间帧在 CNN 输入通道里较早混合，跨时间、跨目标的关系没有显式 token 结构。

[ViNT](ViNT.md) 把每帧编码成独立 token，再用 Transformer 建模观测序列与目标的关系。可以把演进先记成：

```text
GNM： 图像沿通道堆叠 → 两路 CNN → 向量拼接 → MLP → 航点
ViNT：每帧 CNN 编码 → 观测 token + 目标条件 token → Transformer → 航点
```

两者仍是确定性航点回归；“左右都有合理路径”的多峰问题，还会引出 [NoMaD](NoMaD.md)。
